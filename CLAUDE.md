# CLAUDE.md

File guides Claude Code (claude.ai/code) working in repo.

## Project

Mobile-first golf game. Vanilla JS + HTML5 Canvas. No build step — open `index.html` direct or serve with Python.

## Running locally

```sh
cd ~/Documents/GitHub/golf-game
python3 -m http.server 8080
```

Desktop: `http://localhost:8080`  
Phone (same WiFi): `http://<your-mac-ip>:8080`

**Admin server (optional):** `python3 tools/bake_server.py` — drop-in replacement for `http.server`, ALSO exposes `/api/search` + `/api/bake`. Powers in-game admin **➕ Add course** button (search course → bake via `fetch_course_global.py` → append `courses/manifest.json` → git commit). Flags: `--port 8080 --no-git --push`. Button admin-gated AND hidden unless `/api/ping` answers — plain static deploy never show it. Course list from `courses/manifest.json` (fallback: hardcoded `FALLBACK_COURSES` in game.js).

## Concurrent Claude Code agents

Many agents can work repo at once. Two independent isolations — **neither need commit or push**:

- **Browser (Playwright):** `.mcp.json` runs Playwright MCP with `--isolated` — each Claude session get own ephemeral Chrome profile, no fight over shared profile dir (`mcp-chrome-*`). Without it, second agent hit `Browser is already in use ... use --isolated`. Isolated mode keep no persistent browser state — fine here (localhost, no logins). Dev server (`python3 -m http.server 8080`) shared; one instance serve all agents.
- **Files (git):** stop agents clobbering edits — give each own **git worktree** (`git worktree add ../golf-game-<name>`, or Agent tool `isolation: "worktree"`). Each worktree = separate working copy, own branch; merge when done. Commit/push only for sharing results, never prerequisite for parallel agents.

  - **HOLE data** — `HOLE` built at runtime by `setHole()` from loaded course data (`surfaces` = polygon arrays per type); `FALLBACK_HOLE` = hardcoded par 4 if fetch fail

## Coordinate system

Per-hole world bounds (`WORLD.w/h`, set by `setHole`); origin top-left, tee bottom, pin near top. Scale **fixed** at `YARDS_PER_UNIT` (≈3 yds/unit, from course JSON) — given swing = same distance every hole. `view.scale`, `view.ox`, `view.oy` map world→screen via camera rect; `wx(x)`, `wy(y)`, `ws(v)` convert coords/sizes. Recomputed every window resize + hole change.

## Course data pipeline (Phase 2)

Real geometry from OpenStreetMap via Overpass API (`golf=green|fairway|tee|bunker|water_hazard|hole`). Strategy: **pre-bake, not live-fetch** — `tools/fetch_course.py` query one course (by boundary way id), project lat/lon → per-hole world units (tee→pin oriented "up", fixed yards/unit), write normalized `courses/<id>.json` game fetch statically.

Geometry **real-first**: greens, bunkers, water, tees, **fairways**, **rough** (`golf=rough`), plus **woods/cartpaths/grass** from real OSM polygons (`golf=*`, `natural=wood|water`, `landuse=grass`). Hole lines ordered by leading int in `ref` (handles `"7"` and `"7 - #2"`), deduped by number. Fairways/bunkers/rough/woods/cartpaths/grass assigned to **nearest hole** (centroid→centerline). Fairway corridor **synthesized only as fallback** for holes with no mapped fairway (links courses like St Andrews) — tool print how many holes fell back.

**Rough vs fairway inference:** `surfaceAt()` return `"rough"` as implicit default (any point not in water/bunker/green/fairway/tee/woods polygon); mapped `golf=rough` now also baked as explicit `rough` surface (mostly aid rendering — physics already default rough). Real accuracy fix = **aerial-carved fairways**: holes with no OSM fairway, bake replace crude fixed-width corridor with **variable-width ribbon measured from Esri aerial** (`measure_fairway_ribbon`/`carve_synth_fairway` in `fetch_course.py`; `carve_synth_fairways` in global tool). Classify mown fairway grass by HSV (`is_fairway_px`, `FW_*` constants — may need per-course tuning), march perpendiculars off tee→pin centerline find each edge, **clamp width ≤ fixed corridor** so world bounds stay valid. Need **Pillow** (optional — `try: from PIL import Image`); without it, or classify fail, fall back to fixed corridor (e.g. Pinehurst sandy no-rough holes no carve, keep rectangle).

**Aerial imagery:** tool also bake one north-up **Esri World Imagery** JPG per hole into `courses/img/<id>/hole<N>.jpg` (keyless), plus pixel→world affine `aerial.toWorld=[a,b,c,d,e,f]` (`world.x=a*px+b*py+c`, `world.y=d*px+e*py+f`). Game draw photo as hole base, rotated to play "up" via affine — no image processing for *rendering* (Pillow not required there). `--no-imagery` skip. Pillow **is** used (optional) to carve synth fairways from baked aerial — see "Rough vs fairway inference" above.

**Imagery source (Esri vs NAIP — monetization gate):** Esri World Imagery free ONLY non-revenue — terms forbid monetized apps (ads/subscriptions). So `fetch_course.py` expose `IMAGERY = {esri, naip}`, both bake tools take `--imagery {esri,naip}` (default `esri`). **NAIP** (USDA National Agriculture Imagery Program, via The National Map `USGSNAIPImagery/ImageServer/exportImage`) = **public domain, commercial-OK, keyless, US-only**, identical ArcGIS export API — license-clean swap. Baked `aerial.src` field record `"esri"|"naip"`; game on-map credit (`drawAttribution` in game.js) read it → "Imagery: USGS / NAIP" vs "Imagery © Esri" (+ always "© OpenStreetMap contributors" for OSM-derived courses; Originals skip OSM line). **`tools/rebake_naip.py`** batch-swap every US (`region:"USA"`) course to NAIP in place (resumable — skip `aerial.src=="naip"`; git-restorable; boundary ids from `courses/index.json` + `OVERRIDES` map for hand-baked): `python3 tools/rebake_naip.py [--dry-run|--only a,b|--limit N|--force]`. As of swap, **96/97 US courses on NAIP**; lone holdout `crystal-lake-haverhill` (not mapped `leisure=golf_course` in OSM → no boundary to rebake, stay Esri). **Non-US courses (St Andrews UK, Middle East) + fictional Originals stay Esri** (no NAIP coverage) — need different commercial-OK source (e.g. paid Mapbox) to be ads-legal.

**Aerial surface mask (OOB + fairway/rough from what you SEE):** OSM polygons make OOB inconsistent (only `natural=wood` counted — neighborhoods/roads/parking defaulted playable rough), fairway/rough coarse. So bake also classify aerial per-pixel into coarse **label raster** (`courses/img/<id>/surfacemask.png`, palette `OB=0 / FAIRWAY=1 / ROUGH=2 / WOODS=3`) + `surfaceMask:{file,w,h,toWorld}` affine. `build_surface_mask`/`_classify_px` in `fetch_course.py` (wired into `fetch_course_global.py` after aerial download): green-turf by HSV (reuse `is_fairway_px` band); fairway-vs-rough by **brightness split** (Otsu over green pixels → `_otsu`, mostly kill per-course tuning); woods = dark + high local edge energy (`FIND_EDGES`+`BoxBlur`); everything non-green = **OOB only outside playing envelope** — inside it, non-turf (sand/path/dirt) just rough, so fairway bunker not mistaken for parking lot. Envelope = **union** of OSM boundary polygon, buffered hole centerlines (`MASK_CORRIDOR_UNITS`), OSM play polygons (fairway/green/tee/bunker), all dilated outward by `MASK_ENV_DILATE_UNITS` — parcel lines often cut through real dunes/fairway edges (coastal + multi-parcel courses). Outside envelope, **sand-looking pixels rescued to rough** (bright/warm/low-sat, `MASK_SAND_*`) within `MASK_SAND_NEAR_UNITS` of it — sand never OB. Despeckled (`ModeFilter`), OSM `woods` unioned in as strong prior. **Shadow-streak guards** (tree shadows across fairways on leafless/low-sun aerials classify as woods = phantom mid-fairway penalty): heuristic WOODS demoted to ROUGH within `MASK_WOODS_CORRIDOR_UNITS` of hole centerline and within `MASK_WOODS_FW_HALO_UNITS` of mapped fairway (OSM-mapped woods repainted after — real dogleg forest survive), mapped OSM fairway polygons pasted in as FAIRWAY ground truth last. Tunables: `MASK_*` constants. Pillow-optional + guarded (no Pillow / classify fail → no `surfaceMask` key). `--no-mask` skip. **Game side:** `loadSurfaceMask`/`maskClassAt` (game.js) decode PNG once (nearest-palette → `Uint8` labels), sample in `surfaceAt()` — OSM stay authoritative for green/bunker/water/tee, then **mask decide OB vs playable** (envelope already fold in boundary polygon; fairway/rough/woods/`ob`), then vector `boundary` polygon (OB outside it, except mapped fairway) cover off-mask points, then OSM polygons on no-mask holes. `tools/remask_courses.py` rebuild every course mask offline from baked aerial + JSON (no Overpass); `--audit` print OB-in-fairway / OB-near-centerline metrics. New `"ob"` surface mirror woods in `friction`/`bounce`/`lie`; OOB penalty (`woods`+`ob`) gated by `TUNE.obPenalty` (default on = +1 & drop at `lastSafe`). `drawOOBOverlay` draw OB+woods cells as red tint through aerial transform (gated by `showOOB` button).

## Ball flight & physics

Swing = **putt** (on green: stay grounded, roll with slope-aware break — see Topographic green) or **full shot** (airborne projectile). State carry `z` (height), `vz` (vertical velocity), `spin`. `update()` dispatch to `flightStep` (gravity arc + sidespin curve + land/bounce) or `rollStep` (per-surface friction + hole capture + water). Flight calibrated so max swing *carry* `YARDS.maxCarry`; bounce + rollout add more. Shot shape from swipe curvature (`curveFromPath`). Rendered with ground shadow at `(x,y)`, ball lifted by `z`.

Lip-out: rolling ball entering `holeRadius` at speed ≥ `captureSpeed` reflect off rim (0.5 restitution); slow enough → sink (airborne balls can't drop). Water: ball land/stop in water → +1 penalty, reset to `state.lastSafe`. Per-surface `bounce` values = placeholders for real per-course data from future golf API.

**Holding greens:** full shot first touchdown convert straight to roll (`arcFlightStep` landing — `bounce.{e,h}` only apply later ballistic hops, e.g. rammed-putt lip hops). Release distance `Dr` governed by landing check — weighted blend of club backspin (`spinN`) + descent steepness (`checkLandW·steep` from club `land` angle) — mid/long irons hold like tour (5i ≈ 8yd rollout, 7i one-hop, 9i–LW check back a touch, driver release ~37yd). Chips set `fl.noLandCheck`, keep legacy spin-slider-only release. **Flighted high spinner:** right-gutter **FLIGHT slider** (`flightBias` 0..1 — shared `#chip-spin` widget, relabeled by `syncSpinSlider()` when off green outside chip range; in chip range stay chip SPIN slider) throw it higher/spinnier: land steeper + check harder, up to −5% carry (folded into club-carry readout live), ride wind harder. One-shot: consumed + reset on launch. (Replaced earlier swipe-length gesture — length too entangled with aim/power.)
