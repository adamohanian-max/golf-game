## Concurrent Claude Code agents

Multiple agents can work this repo at once. Two independent isolations — **neither needs a commit or push**:

- **Browser (Playwright):** `.mcp.json` runs the Playwright MCP with `--isolated`, so each Claude session gets its own ephemeral Chrome profile instead of fighting over one shared profile dir (`mcp-chrome-*`). Without it a second agent hits `Browser is already in use ... use --isolated`. Isolated mode keeps no persistent browser state — fine here (localhost, no logins). The dev server (`python3 -m http.server 8080`) is shared; one instance serves all agents.
- **Files (git):** to stop agents clobbering each other's edits, give each its own **git worktree** (`git worktree add ../golf-game-<name>`, or the Agent tool's `isolation: "worktree"`). Each worktree is a separate working copy on its own branch; merge when done. Committing/pushing is only for sharing results, never a prerequisite for running agents in parallel.

Shared helpers: `stripes()`, `withClip()`, `tracePoly()`, `strokePolyline()`, `drawGreen(photo)`. **Topographic green**: a synthesized (deterministic, no real elevation) height field per green → contour lines via marching squares (`buildGreenTopo()`/`contourSegments()`, precomputed in `setHole`), drawn in both modes. **This same field drives putting break** — each green exposes `h(x,y)` + analytic `grad(x,y)`; `greenSlopeAt()` returns the downhill gradient and `rollStep` accelerates the ball along it (`TUNE.slopeAccel`, gated by `TUNE.slopeStopSpeed` so a settled ball doesn't creep). So what you see (contours) is what breaks. Real LiDAR (USGS 3DEP) can later replace `grad`/`h` per-green without touching downstream. **Shaded-relief topo**: a soft hillshade overlay (NOT a rainbow heatmap) shown only on the **green in play** + the **target green** (`greensInPlay()` = green under the ball and under the pin). Per green, `buildGreenRelief()` bakes a small offscreen raster (light/shadow from the height-field normal, NW light, + a whisper of warm tint on the steepest spots); `drawGreenRelief()` clips to the green and draws it through the view transform (composes `dpr·(view∘m)` like `drawAerial`, `imageSmoothingEnabled` → smooth, rotates with the camera). It's **whisper-faint always-on** (`TUNE.reliefAmbient`) and the slope toggle (`#hm-slope` in the HUD menu) **boosts intensity** (`TUNE.reliefFull`) and adds **flow dots** — particles drifting downhill along the green's gradient (`updateFlowDots`/`drawFlowDots`, per-green `g._flow` cache; speed AND brightness ∝ local slope; `TUNE.flow*` tunables). The old static fall-line arrows (`drawFallArrow`/`drawGreenArrows`) are available via the **Break arrows** toggle (`#hm-arrows` in the HUD menu → `breakArrows`, per-device localStorage) — arrows replace the dots when on. Relief tunables: `reliefAmbient/reliefFull/reliefExag/reliefShade/reliefTint`. **3D green inspect view**: the `#green-view-btn` HUD button (visible when the ball is at rest with a green in play) opens a full-screen tilted 3D mesh of the green — manual axonometric projection + painter's algorithm in canvas 2D (`openGreenView`/`buildGreenViewMesh`/`drawGreenView`, `greenView` state; `TUNE.gv*` tunables). Mesh baked once per open (hillshade × height-tint cell colors, rim-clipped boundary quads); per-frame = project + sorted quad fills. Drag rotates, vertical drag/pinch/scroll tilts (clamped `gvTiltMin`–`gvTiltMax`), tap/Escape closes. Tilting is honest because the **shadow slab** under the surface sits at one constant height — it always reads as flat ground, and the side wall between the surface rim and the slab shows the true elevation gap; height exaggeration stays modest (`TUNE.gvHeight`). Swing input suspended while open (`canSwing()` gates on `!greenView`), draped contours + flow dots + cup/flag/ball markers drawn on the surface. Greens-only (the old fabricated fairway field + rainbow `slopeColor`/`drawSlopeHeat` were removed). **Cinematic 3D landing**: a great off-green shot auto-cuts to the pin's green in 3D as the ball descends — `maybeArmCine()` (last statement of `launchShot`/`slottedLaunch`) runs `simShotRest()`, a side-effect-free forward sim replaying the exact step physics (the drift-prone math is shared via pure helpers `landingRelease()`/`resolveCup(rand)`, called by BOTH the live steps and the sim, so prediction can't drift); trigger = predicted holed / lip-out / rest on a green within `clamp(shotYds·cineFtPerYd, cineMinFt, cineMaxFt)` of the cup. Armed → `cinePending`; `tickCine()` (in `loop`) cuts in past the apex (`cineCutFrac`); `drawCine()` renders via the shared `paintGreen3D()` painter + the LIVE ball projected each frame (real physics keeps running underneath — it's render-only), with a scripted push-in (`cineZoomIn/cineZoomMs`) + gentle orbit (`cineYawDrift`); closes `cineHoldMs` after rest, or via `showResult` on a hole-out; tap/Escape skips. `canSwing()` gates on `!cine`; per-device toggle `#hm-cine` → `cineEnabled` (`golf.cineLanding`). Aerial draw composes `dpr·(view ∘ aerial.toWorld)` and `drawImage`.

## Coordinate system

Per-hole world bounds (`WORLD.w/h`, set by `setHole`); origin top-left, tee at bottom and pin near the top. Scale is **fixed** at `YARDS_PER_UNIT` (≈3 yds/unit, from the course JSON) so a given swing means the same distance on every hole. `view.scale`, `view.ox`, `view.oy` map world→screen via the camera rect; `wx(x)`, `wy(y)`, `ws(v)` convert coords/sizes. Recomputed on every window resize and hole change.

## Course data pipeline (Phase 2)

Real geometry comes from OpenStreetMap via the Overpass API (`golf=green|fairway|tee|bunker|water_hazard|hole`). Strategy is **pre-bake, not live-fetch**: `tools/fetch_course.py` queries one course (by its boundary way id), projects lat/lon → per-hole world units (tee→pin oriented "up", fixed yards/unit), and writes a normalized `courses/<id>.json` the game fetches statically.

Geometry is **real-first**: greens, bunkers, water, tees, **fairways**, **rough** (`golf=rough`), plus **woods/cartpaths/grass** come from real OSM polygons (`golf=*`, `natural=wood|water`, `landuse=grass`). Hole lines are ordered by the leading int in their `ref` (handles `"7"` and `"7 - #2"`), deduped by number. Fairways/bunkers/rough/woods/cartpaths/grass are assigned to the **nearest hole** (centroid→centerline). A fairway corridor is **synthesized only as a fallback** for holes with no mapped fairway (links courses like St Andrews) — the tool prints how many holes fell back.

**Rough vs fairway inference:** `surfaceAt()` returns `"rough"` as the implicit default (any point not in a water/bunker/green/fairway/tee/woods polygon); mapped `golf=rough` is now also baked as an explicit `rough` surface (mostly aids rendering — physics already defaults to rough). The real accuracy fix is **aerial-carved fairways**: for holes with no OSM fairway, the bake replaces the crude fixed-width corridor with a **variable-width ribbon measured from the Esri aerial** (`measure_fairway_ribbon`/`carve_synth_fairway` in `fetch_course.py`; `carve_synth_fairways` in the global tool). It classifies mown fairway grass by HSV (`is_fairway_px`, `FW_*` constants — may need per-course tuning), marches perpendiculars off the tee→pin centerline to find each edge, and **clamps width ≤ the fixed corridor** so world bounds stay valid. Needs **Pillow** (optional — `try: from PIL import Image`); without it, or on classification failure, it falls back to the fixed corridor (e.g. Pinehurst's sandy no-rough holes don't carve and keep the rectangle).

**Aerial imagery:** the tool also bakes one north-up **Esri World Imagery** JPG per hole into `courses/img/<id>/hole<N>.jpg` (keyless), plus a pixel→world affine `aerial.toWorld=[a,b,c,d,e,f]` (`world.x=a*px+b*py+c`, `world.y=d*px+e*py+f`). The game draws the photo as the hole base, rotated to play "up" via that affine — no image processing needed for *rendering* (Pillow not required there). `--no-imagery` skips it. Pillow **is** used (optionally) to carve synth fairways from the baked aerial — see "Rough vs fairway inference" above.

**Imagery source (Esri vs NAIP — the monetization gate):** Esri World Imagery is free ONLY for non-revenue use — its terms forbid monetized apps (ads/subscriptions). So `fetch_course.py` exposes `IMAGERY = {esri, naip}` and both bake tools take `--imagery {esri,naip}` (default `esri`). **NAIP** (USDA National Agriculture Imagery Program, via The National Map's `USGSNAIPImagery/ImageServer/exportImage`) is **public domain, commercial-OK, keyless, US-only**, and uses the identical ArcGIS export API — the license-clean swap. The baked `aerial.src` field records `"esri"|"naip"`; the game's on-map credit (`drawAttribution` in game.js) reads it → "Imagery: USGS / NAIP" vs "Imagery © Esri" (+ always "© OpenStreetMap contributors" for OSM-derived courses; Originals skip the OSM line). **`tools/rebake_naip.py`** batch-swaps every US (`region:"USA"`) course to NAIP in place (resumable — skips `aerial.src=="naip"`; git-restorable; boundary ids from `courses/index.json` + an `OVERRIDES` map for hand-baked ones): `python3 tools/rebake_naip.py [--dry-run|--only a,b|--limit N|--force]`. As of the swap, **96/97 US courses are on NAIP**; the lone holdout is `crystal-lake-haverhill` (not mapped as `leisure=golf_course` in OSM → no boundary to rebake, stays Esri). **Non-US courses (St Andrews UK, Middle East) + fictional Originals stay Esri** (no NAIP coverage) and would need a different commercial-OK source (e.g. paid Mapbox) to be ads-legal.

**Aerial surface mask (OOB + fairway/rough from what you SEE):** OSM polygons make OOB inconsistent (only `natural=wood` counted — neighborhoods/roads/parking defaulted to playable rough) and fairway/rough coarse. So the bake also classifies the aerial per-pixel into a coarse **label raster** (`courses/img/<id>/surfacemask.png`, palette `OB=0 / FAIRWAY=1 / ROUGH=2 / WOODS=3`) + a `surfaceMask:{file,w,h,toWorld}` affine. `build_surface_mask`/`_classify_px` in `fetch_course.py` (wired into `fetch_course_global.py` after the aerial downloads): green-turf by HSV (reuses `is_fairway_px`'s band); fairway-vs-rough by **brightness split** (Otsu over the green pixels → `_otsu`, mostly removes per-course tuning); woods = dark + high local edge energy (`FIND_EDGES`+`BoxBlur`); everything non-green is **OOB only outside the playing envelope** — inside it, non-turf (sand/path/dirt) is just rough, so a fairway bunker isn't mistaken for a parking lot. The envelope is the **union** of the OSM boundary polygon, the buffered hole centerlines (`MASK_CORRIDOR_UNITS`) and the OSM play polygons (fairway/green/tee/bunker), all dilated outward by `MASK_ENV_DILATE_UNITS` — parcel lines often cut through real dunes/fairway edges (coastal + multi-parcel courses). Outside the envelope, **sand-looking pixels are rescued to rough** (bright/warm/low-sat, `MASK_SAND_*`) within `MASK_SAND_NEAR_UNITS` of it — sand is never OB. Despeckled (`ModeFilter`), OSM `woods` unioned in as a strong prior. **Shadow-streak guards** (tree shadows across fairways on leafless/low-sun aerials classify as woods = phantom mid-fairway penalty): heuristic WOODS is demoted to ROUGH within `MASK_WOODS_CORRIDOR_UNITS` of a hole centerline and within `MASK_WOODS_FW_HALO_UNITS` of a mapped fairway (OSM-mapped woods repainted after, so real dogleg forest survives), and mapped OSM fairway polygons are pasted in as FAIRWAY ground truth last. Tunables: `MASK_*` constants. Pillow-optional + guarded (no Pillow / classify fail → no `surfaceMask` key). `--no-mask` skips it. **Game side:** `loadSurfaceMask`/`maskClassAt` (game.js) decode the PNG once (nearest-palette → `Uint8` labels) and sample it in `surfaceAt()` — OSM stays authoritative for green/bunker/water/tee, then the **mask decides OB vs playable** (its envelope already folds in the boundary polygon; fairway/rough/woods/`ob`), then the vector `boundary` polygon (OB outside it, except mapped fairway) covers off-mask points, then OSM polygons on no-mask holes. `tools/remask_courses.py` rebuilds every course's mask offline from the baked aerial + JSON (no Overpass); `--audit` prints OB-in-fairway / OB-near-centerline metrics. New `"ob"` surface mirrors woods in `friction`/`bounce`/`lie`; OOB penalty (`woods`+`ob`) is gated by `TUNE.obPenalty` (default on = +1 & drop at `lastSafe`). `drawOOBOverlay` draws the OB+woods cells as a red tint through the aerial transform (gated by the `showOOB` button).

Default course: **Pinehurst No. 2** (`courses/pinehurst-no2.json` + `courses/img/pinehurst-no2/`, 11/18 holes with real fairways). Re-bake:
`python3 tools/fetch_course.py --boundary-way 1358696570 --id pinehurst-no2 --name "Pinehurst No. 2"`

## Key tunables (`TUNE` in game.js)

| Constant | Effect |
|---|---|
| `powerFactor` / `maxPower` | Swipe speed → launch speed; derived from `YARDS.maxCarry` projectile range |
| `launchAngleDeg` / `gravity` / `airDrag` | Ball-flight arc shape & hang time |
| `spinFactor` | How hard a curved swipe bends flight (draw/fade) |
| `bounce.<surface>.{e,h}` | Landing: `e` vertical restitution, `h` horizontal speed retained |
| `bounceStopVz` | Downward speed below which bouncing stops → rolling |
| `captureSpeed` | Max ball speed to drop into cup (higher = more forgiving) |
| `friction.*` | Per-surface rolling velocity multiplier per frame (fairway/rough/bunker/water; lower = more friction). Green is separate (constant deceleration, see below) |
| `greenDecel` | Green roll: constant deceleration/frame, derived from stimp (`GREEN_DECEL_K / greenSpeed`); realistic putt rollout |
| `slopeAccel` | Putting break: downhill accel per unit of green-field gradient (folds vertical scale + gravity into one knob) |
| `slopeStopSpeed` | Below this roll speed slope is ignored, so a settled ball rests instead of creeping |
| `checkSpinW` / `checkLandW` / `checkLandRef` / `checkLandSpan` | Landing check = blend of backspin AND descent steepness (TrackMan: irons land 46–52°, which is why a tour 5i holds). `steep = (land° − ref)/span` clamped 0..1; chips opt out (`fl.noLandCheck`, spin-slider only) |
| `spinCheckK` / `rolloutK` / `spinBackMax` | Check strength on the release `Dr = vh·rolloutK·(1 − check·spinCheckK)` (<0 spins back, capped at `spinBackMax` units) |
| `lieLand` | Per-lie land-angle multiplier — flyers from rough come in shallower AND lower-spin, so they release |
| `flightHi*` | Flighted high spinner: swipe path length ≥ `flightHiLen`×screen diagonal (touch/mouse only — power is release SPEED, so length is a free channel) → apex×`flightHiApex`, land+`flightHiLand`°, spin×`flightHiSpin`, carry×`flightHiCarry`, wind×`flightHiWind` |

## Ball flight & physics

A swing is either a **putt** (on the green: stays grounded, rolls with slope-aware break — see Topographic green) or a **full shot** (airborne projectile). State carries `z` (height), `vz` (vertical velocity), `spin`. `update()` dispatches to `flightStep` (gravity arc + sidespin curve + land/bounce) or `rollStep` (per-surface friction + hole capture + water). Flight calibrated so a max swing *carries* `YARDS.maxCarry`; bounce + rollout add more. Shot shape comes from swipe curvature (`curveFromPath`). Rendered with a ground shadow at `(x,y)` and the ball lifted by `z`.

Lip-out: a rolling ball entering `holeRadius` at speed ≥ `captureSpeed` reflects off the rim (0.5 restitution); slow enough → sinks (airborne balls can't drop). Water: ball lands/stops in water → +1 penalty, resets to `state.lastSafe`. Per-surface `bounce` values are placeholders for real per-course data from the future golf API.

**Holding greens:** a full shot's first touchdown converts straight to a roll (`arcFlightStep` landing — `bounce.{e,h}` only applies to later ballistic hops, e.g. rammed-putt lip hops). The release distance `Dr` is governed by the landing check — a weighted blend of the club's backspin (`spinN`) and descent steepness (`checkLandW·steep` from the club's `land` angle), so mid/long irons hold like the tour (5i ≈ 8yd rollout, 7i one-hop, 9i–LW check back a touch, driver releases ~37yd). Chips set `fl.noLandCheck` and keep the legacy spin-slider-only release. **Flighted high spinner:** a long deliberate swipe (path length, not speed — see `flightHi*`) throws it higher/spinnier: lands steeper + checks harder, −5% carry, rides wind harder; "High ball · extra spin" toast on launch. Trackpad wheel swipes can't express it (gesture length ∝ speed there).
